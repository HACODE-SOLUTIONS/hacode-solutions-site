## Common footguns

### 1. Missing decision-maker

If Maya “usually decides” but Omar “sometimes signs off,” you do **not** have a decision-maker. Name one human for **scope**; optionally a different human for **AP**. Kickoff without a scope owner produces soft scope and unpaid extras.

**Fix:** `GAP: decision-maker` on intake; refuse “scope locked” until confirmed in writing or on the decision-lock list.

### 2. Unpaid extras

Slack “quick asks” feel free; they are not. If it is not on `SCOPE-CHECKLIST.md` In-scope, it is Out.

**Fix:** Use the scope-change script (A defer / B swap / C expand). Do not start C-work before written approval and a row in `INVOICE-MILESTONES.md` change orders.

### 3. Soft scope

Items that are neither In nor Out become ghosts that explode in week three.

**Fix:** Default ambiguous → **Out**. Read the Out list aloud in kickoff. Silence is not approval.

### 4. Treating this kit as Product #1

This kit will not make Checkout webhooks correct.

**Fix:** `COMPOSE-WITH-PRODUCT1.md` when end-user paid unlock is in v1.

### 5. Secrets in shared Docs

Pasting `sk_live_` into a client Google Doc that “everyone can edit” is an incident waiting to happen.

**Fix:** `ACCESS-OWNERS.md` stores owners and vault locations—not secret values.

### 6. Three homes for the truth

Notion + Docs + Markdown copies drift.

**Fix:** Pick Path A, B, or C in `START-HERE.md` once per client.

### 7. Kickoff without decision-lock

A friendly chat is not onboarding.

**Fix:** Run `KICKOFF-AGENDA.md` table; every row Decide / Defer(date) / Out.

### 8. Invoice template ≠ contract

`INVOICE-MILESTONES.md` does not create enforceable terms.

**Fix:** Point “binding terms live in” at your proposal/contract/email; use this file for rhythm and clarity only.
